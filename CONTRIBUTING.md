# Contributing to Progflow

yo! thanks for checking out the project. honestly, it's pretty cool that you wanna help out. i'm just trying to make something useful for devs, so if you have ideas or found a bug, definitely let me know.

here's the lowdown on how to contribute without making things complicated:

### how to help out
1. **found a bug?** just open an issue and tell me what happened. if you can show me how to break it, even better.
2. **got a cool idea?** i'm all ears. open an issue or just start working on it if you're feeling brave.
3. **wanna code?** fork the repo, do your thing, and send a PR. i'll check it out as soon as i can (usually after school or on weekends).

### some rules (keep it chill)
- **don't break things**: try to run the tests before you send a PR. if you add a new feature, maybe add a test for it too? it helps a lot.
- **clean code is nice**: you don't have to be a genius, but try to keep things readable. simple is usually better than "big brain" code that nobody can understand.
- **be cool**: basically just be nice to everyone. no gatekeeping or being a jerk. we're all just here to build cool stuff.
- **comments**: keep them simple. explain *why* you're doing something if it's not obvious, but don't write a novel.

### technical stuff
- we're using Rust (obviously). try to stick to standard idioms.
- format your code with `cargo fmt`. it keeps everything looking consistent.
- if you're changing the config format, let me know so we don't break everyone's existing flows.

that's about it! thanks again for being awesome. let's build something great.
